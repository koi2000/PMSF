## 0. 结论（先读）

**P1 判定：FAIL。**
- **可解码**的 P1 路径最好 = **tag-frenet 72,367 B / 29.164072 bpv / 1.6384×**（decode 六项全 true），
  比默认忠实路径 34.052 改善 −4.89 bpv，但**没有达到 P1 的 ~24–25 bpv 目标**。
- **polar θ/φ 3-bit 原型（论文 §4.2）速率达标**：**62,271 B / 25.095360 bpv / 1.4099×**，
  几何 `G=13.723 bpv`（论文 horse G=12.9 的 **1.06×**），但 **decode 结构无效**（§4）。
- polar 失效的根因**不是 3-bit 精度**，而是 tag sv=3 编解码器的 **lossless-only 坐标约定**：
  拓扑推断（polygon v0 / Frenet frame 的 t1）依赖**量化整数坐标**推 proxyHalfedge。
  几何一旦有损，decoder 量化坐标与 encoder 不同 ⇒ proxy/frame 翻转 ⇒ fan/tag evolution 分叉。
  §4.3 的三个判别实验把这条钉死（rounds=1 有效；rounds=2 起坏；θ/φ 近无损仍坏）。
- 这条根因与 **P3「真 A&D connectivity」是同一项改造**（把拓扑推断从坐标解耦），
  因此 P2 的 polar 无法单独落地：**P3 是 polar 可解码的前置**（§5）。

纪律核对：默认 APTM 路径 **84,496 B / 34.052088 bpv / md5 与冻结审计逐字节一致**（见 §2）；
全程未用 `PMSF_APTM_USE_RETRI_TAG`（RD 别名）/ `PMSF_APTM_USE_CONQUEST`（no-op）/ 未降 q / 未改变体。

## 1. P1 路径与接线

新增 env-gated 路径（默认路径零改动）：

```
PMSF_APTM_USE_APTM_TAG=1     启用 APTM-Tag 路径（collector/eliminate/管线/reader 全部切换）
PMSF_APTM_TAG_GEOM=cartesian|frenet|polar   几何 coder（默认 cartesian）
PMSF_APTM_TAG_POLAR_LEVELS=N  polar θ/φ 量化级数（默认 8 = 3-bit；用于精度扫描）
PMSF_APTM_QUANT_BITS=12      量化位宽（沿用 APTM 既有键）
```

实现（全部在 `impl/APTM/`，未改 `impl/PCLTTM`、`impl/RD`、`src/predict`、`impl/common`、`docs/memory`）：

| 文件 | 作用 |
|---|---|
| `impl/APTM/compress/APTMTagSymbolCollectOperator.{h,cpp}` | 继承 `PCLTTMTagSymbolCollectOperator`（A&D/tag 连通性 valence + fusedFaceSym），覆写 `collect()`（polar 量化 + 内轮预测链重放）与 `exportToBufferWithRangeCoder()`（容器 sv 改写 64/65）；内联一份与父类逐位同源的 Frenet frame / 整数 lifting 数学 |
| `impl/APTM/decompress/APTMTagSymbolReadOperator.{h,cpp}` | 继承 `PCLTTMTagSymbolReadOperator`：容器 sv 64/65 → patch 回 3 后调父类 import，再把 polar 三元组展开成 Frenet 分量，置 `rcUseFrenetResidual_=true` 走父类的 lifting 反投影 |
| `impl/APTM/APTMTagSchemeVersion.h` | 容器 scheme_version 常量（3 / 64 / 65）与 polar 级数 |
| `impl/APTM/APTMAlgorithm.cpp` | P1 hooks：`collectorFactory`、`eliminate`(=PCLTTMTagEliminate)、`requiresQuantization`、`beforeCompressLoop`(attach `kVPropRDR1`)、`pipelineTuner`(tag 管线参数)、`makeDecompressOptions`/`afterBaseMeshHook`(APTM reader 装配)；未设 env 时逐项与改动前相同 |

为什么**不**复用协议覆盖（`retriangulationProtocol`）：
1. `RETRI_TAG` 是 RD_Tag 别名（产物即 RD 字节，Lead 已裁决禁用）；
2. PCLTTM_Tag 协议覆盖路径自建 `defaultColumnar()` 管线，**不经过本算法的 `pipelineTuner()`**，
   于是 `AnchorPreprocessor` 只在第 0 轮生效、后续轮 anchor 标志被 `resetState` 清掉
   —— 而「anchor 每轮保持不可删、进 base mesh、多送 null_patch」正是 APTM 论文 §3/§4.1 的核心贡献。
   本路径走标准管线，anchor 每轮生效（实测两条路径 anchors 都是 139）。

## 3. polar 实现细节（论文 §4.2 口径）

1. geometry 残差 `r1 = vrPos − barycenter` 先经父类的二阶 curvature predictor → `c = r1 − pred_c2`，
   再由父类内置**可逆整数 lifting** 转到 Frenet 分量 `(c_n,c_t,c_b)`（帧由量化整点位置构造，双端 bit-exact）。
2. polar 量化：`R = round(|c|)`（全精度整数量化单位）；`θ = acos(c_n/|c|) ∈ [0,π]`、
   `φ = atan2(c_b,c_t) ∈ [0,2π)` 各量化到 **8 级（3 bit）**；半径整数 R 不损失角度级。
3. 编码域：`(R, θq, φq)` 三元组直接进父类 bit-plane RC（布局/容器不变，仅 scheme_version=65 标识语义）；
   段字节数见 §2.2。
4. 内轮对称：encoder 在 `collect()` 末尾做两遍重放 —— 先复原父类预测链的原始 `r1`，
   再用**量化后重建残差**重放 decoder 的 `pred_c2` 链并写回邻居 `kVPropRDR1`，
   使「decoder 侧 `residual = unproject(expand(θ,φ)) + pred_dec`」与 encoder 状态逐位一致。

## 4. polar decode 为什么无效（逐组件归因）

### 4.1 现象

polar decode 结构无效：`test_vertices=19,104/19,851`、`test_faces=36,669/39,698`、
nonmanifold edges=887、boundary edges=1,065、counts/connectivity/topology/nearest/remap 全 false；
`coord_match_max=1.75e−3`、`nn_ref_to_test_rmse=3.82e−3`。
decode 过程中 `rdCollectPolygonVerts` 的 D18 探针实测到 **2-cycle digon**（面与其 next 链自成一个 2 环），
即拓扑在解码中途已经损坏。rounds=10 时直接 segfault。

### 4.2 根因（不是 polar 数学）

polar 与 cartesian/frenet 的 **connectivity 段完全相同**（valence 5,393 / fusedFaceSym 16,828 字节，
同一次消除序列、同一 tag evolution），而 cartesian/frenet 用同一 reader 路径 decode 六项全 true。
⇒ 失效只能来自 **坐标依赖的解码分支**，tag sv=3 里只有一处：

- `PCLTTMTagSymbolReadOperator::collectFromDecoded` 对每个首次访问的面调
  `f->normalize_proxy_to_min_position_vertex(bboxMin_, f_quantStep_)`，
  用**量化整数坐标的字典序**选 polygon v0；encoder 在 `collect()` 入口用同一规则 normalize。
  该 proxyHalfedge 同时决定 `residualFrenetFrame()` 的 t1 方向（proxy 两端点差）。
- lossless 时 `q_dec == q_enc`（重建位置就是编码端量化位置）⇒ proxy/frame 一致；
  **几何有损时 `q_dec ≠ q_enc`**（哪怕只差 1 个量化单位）⇒ proxy 可能翻转/改变 ⇒
  ring 起点与 frame 旋转不同 ⇒ fan 对角线、tag evolution、之后的 normalize 连锁分叉 ⇒ digon/丢顶点。
- 这是 PCLTTM Tag sv=3（Phase 2 为了砍掉 edgeSym 流而引入）的 **lossless-only 捷径**；
  RD sv=7 也基于它。任何 lossy 几何 coder 在这个约定下都不可能解码。

### 4.3 判别实验（`test_aptm_p1_decode_boundary.sh`，CSV `APTM_P1_DECODE_BOUNDARY.csv`）

| 实验 | 结果 | 说明 |
|---|---|---|
| rounds=1, θ/φ=8 | counts/conn/topo/remap **true**，19,851 顶点 | 单轮环顶点全是无损 base mesh ⇒ polar 数学本身正确；nearest=false 只是 3-bit 有损（论文口径允许） |
| rounds=2, θ/φ=8 | counts/conn/topo false | 首轮插入顶点（有损）进入环 ⇒ 结构开始坏 |
| rounds=150, θ/φ=1,048,576（角度≈无损 0.0001°） | **仍坏**（18,423 顶点） | **排除「3-bit 精度不够」**：失效与角度精度无关 |
| rounds=150, θ/φ=8（论文口径） | 坏（19,104 顶点） | 论文口径直接受同一根因影响 |

结论：polar 速率（25.10 bpv，几何 1.06× 论文）是**真实的**，但当前 tag 解码架构无法把它解成有效网格；
必须先做 **P2 前置 = 拓扑推断去坐标化**（= P3 真 A&D connectivity 的一部分）。
